# 排障手册 · formant_synth

> 这本手册记录的是**这个项目里真正付过代价的教训** —— 代码里读不出来的那部分。
> 动这个仓库之前先通读一遍，能省掉很多时间。

---

## 0. 三条验证纪律（最重要的一页）

### 1）先验工具，再验结论

这个项目里，**验证器自己出错的次数比被验证的代码还多**：

- 有一轮音频工作，**7 个坑里有 6 个是工具自身的 bug**；
- 另一轮 4 个错里 **2 个是分析脚本**（其中一个拿"脉冲源梳状谱"去比"真机平滑谱"，
  等于**拿梳子量布**，识别率算出 0/100）；
- 做发布包那轮，**2 个坑全在生成器里**（见 §2）。

**做法**：给每个工具写 `--selftest`，自检不过就别看图、别下结论。

### 2）数字要跑出来，不要手数

- 曾凭印象说"13 对辅音相同"，实跑探针是 **17 组 / 38 条**；
- 参数表要由探针**实跑生成**，不是从代码里手抄；
- 回归对比用 **SHA256**，不用"看起来一样"。

### 3）「实测过」三个字要能兑现

写之前先自问：**怎么测的？原始字节/原始数字在哪？**

这个项目里有过一次教训：声称"某工具支持 zstd，我实测过了"，
其实只验证了那个工具**存在**、没验证它**能解 zstd**。
这类"听起来合理、我也没细看，就当结论说了"的断言，是**最贵的一类错误** ——
它不是能力问题，是**纪律问题**。

## 1. ★ 静默失效清单（这类 bug 最贵，因为没有报错）

这个项目里最危险的 bug 是**不报错、只是没声音 / 没效果**。
历史上一共出现过 4 次，每次都是靠**回读字节**才发现的：

### A) SysEx 状态字节写成 `FF 01`（meta 文本）而不是 `F0`

字节和长度都对 → 音源收不到 GS Reset → **不报错，只是没声音**。

- 判据：SysEx 的状态字节是 **`F0`**，不是 `FF 01`。
- 检查：看输出文件 tick 0 的字节。

### B) SysEx 漏写 VLQ 长度前缀

SysEx 事件的正确写法是 **`F0` + VLQ 长度 + 载荷（含结尾 `F7`）**。

只写 `F0` + 载荷时，解析器会把载荷的**第一个字节当成长度**
（例如 `0x41` → 65 字节），**一下跳过整条轨** ——
后面所有事件（RPN / CC11 / 音符）全部消失，**而且没有任何报错**。

> ⚠️ 注意区分两种写法，很容易搞混：
> - **协议里描述**的 GS Reset 是 `F0 41 10 42 12 40 00 7F 00 41 F7`（10 字节，**光看内容**）
> - **真正落盘**时必须插一个长度字节：`F0 0A 41 10 42 12 40 00 7F 00 41 F7`
>
> 手写 SMF 时照抄 `Test_Tools/Make_Test_Smf.cpp` 的 `SysEx()`。

### C) 缺 CH10 解锁 SysEx

GS 下噪声通道（CH9，MIDI 通道 10）默认是鼓通道。
不发 `F0 41 10 42 12 40 10 15 00 1B F7` 把它解锁，**CH9 完全静音**，
现象同样是"没有报错、只是听不见"。

### D) 配置文件被用错编码写回

项目的播放器配置 `MidiPlayer.ini` 是 **GBK(ANSI)** 编码。
用 UTF-8 写回去会让里面的中文路径变成乱码（`素材` → `锟截诧拷`），
**音源路径失效 → 播放器彻底没声音**，而 **UI 一切正常、歌单照走**。

副作用：曾因此录到 41 MB 纯静音，还误判成"音源没进录制链"。

- **改任何 `.ini` 前先看字节确认编码；改后核对那一行。**

### 通用判据

凡是"程序说成功、但听不到 / 看不到效果"，第一步永远是**回读输出文件的字节**，
而不是怀疑耳朵或音源。

`smf_note_peek`（音符结构）与 `smf_detect_cli`（输入侧读数）是**两套独立解析器**，
互相矛盾时，**原始字节 dump 才是真相**。

## 2. 已定位但**根因未明**的坑：`Expression_Mapper` 漏读 CC11

### 现象

同一个 tick 上，如果**先**写 RPN 的四条 CC（`101`/`100`/`6`/`38`）、**再**写 `CC11`，
则 `smf_detect_cli` 报「**0 个 CC11 事件**」，而且时间线长度也会算错。

### 最小复现

用 `make_demo_song` 的探针模式生成四种排列，分别读一遍：

```
make_demo_song out.mid --probe          # 裸：只有 CC11 + 一个音符
make_demo_song out.mid --probe-sysex    # 加一段合法 SysEx
make_demo_song out.mid --probe-rpn      # RPN 在 CC11 之前
make_demo_song out.mid --probe-rpnlast  # RPN 在 CC11 之后
```

实测结果：

| 排列 | 读到的 CC11 数 | 报的时间线长度 |
|---|---|---|
| 裸 | **1** ✅ | 1 个四分音符 |
| SysEx + CC11 | **1** ✅ | 1 个四分音符 |
| **RPN + CC11** | **0** ❌ | 30 个四分音符 |
| CC11 + RPN（调换顺序） | **1** ✅ | 17 个四分音符 |

trk 字节（39 B，`--probe-rpn`）：

```
00 FF 03 05 "Probe" 00
B0 65 00  B0 64 00  B0 06 0C  B0 26 00     ← RPN 四条
00 B0 0B 64                                 ← 这条 CC11=100 读不到
00 90 3C 64   83 60 80 3C 40   00 FF 2F 00
```

### 已排除

- **不是产品代码的通病**：工程里其他含 CC11 的样本文件都能正常读出（一个读到 1 条、
  产品自己写出的 17 轨读到 31 条）。
- **不是 SysEx 写法问题**：修好 SysEx 长度前缀后，SysEx 那一路正常。
- **不是"tick 0 的 CC11 被默认值吃掉"**：裸探针的 CC11 也在 tick 0，读得到。
- **不是通道写错**：都是 `B0`（通道 1）；同一批 RPN 本身也读得到（弯音范围正确报 12）。

### 嫌疑点（按可能性排序）

1. `Expression_Mapper.cpp` 的 `scan()` 里 **running status 在 meta / sysex 之后没有被清掉**
   —— MIDI 规范要求这两类事件清除 running status。
   多轨文件里一旦出现"长度字节恰好 < 0x80"的 meta，就可能把下一条事件错认成上一条的延续。
2. `CC101/CC100/CC6/CC38` 这四条被当成别的宽度处理，导致读取位置走偏。
3. `readVlq()` 在某个字节上多读/少读一个 —— 但它对裸探针和 SysEx 都对。

### 怎么查（别用脚本抠字节）

1. 在 `scan()` 的 while 循环里加**临时**打印：每次迭代打
   `pos / status / kind / channel / absTick`，两种排列各输出一份，**diff 第一次出现分歧的那一行**。
2. 或者把 `--probe-rpn` 的 RPN 四条逐个删掉（先删 CC38、再删 CC6…），二分出是哪一条触发的。
3. 写一个**独立解析器**读同一个文件对照 —— 两套解析器对不上时，原始字节 dump 才是真相。

### 临时规避

**把 CC11 写在 RPN 之前。** 工程里所有能正常读出 CC11 的文件恰好都是这个顺序。

## 3. 其他已定位的坑（按主题）

### 解析 / 协议类

| 坑 | 症结 |
|---|---|
| **SMF 是大端** | `MThd` 块长必须 `00 00 00 06`。写成小端 → 产品报"读不到 PPQN"。（WAV 是小端，两套 helper 不能共用） |
| **Program Change 只有 1 个数据字节** | 不是 2 个。按 2 个读会错位 |
| **处理 running status 时 `pos += 2` 会错位** | 不同事件类型的数据字节数不同 |
| **系统探测：GM/GM2 要全匹配、GS/XG 只看头 + 头变化** | 协议只给了四条签名，不加"头变化"判据会误判一堆通道重设消息 |
| **meta 事件的长度是 VLQ** | 不是定长 |
| **`0x01E0` 不是 224，是 480** | 手算 hex 时的运算符优先级 |

### 算法 / 数学类

| 坑 | 症结 |
|---|---|
| **衰减曲线的积分写错** | 错：`x·ln(1+x) − x + 0.5x²`（会先变负 → 曲线先升后降）。对：`(1+x)·ln(1+x) − x`。**公式一定要用数值积分对一遍。** |
| **"公式对" ≠ "画得对"** | 只放两个端点用直线连，形状完全表现不出来。曲线要**按像素宽度采样**验证 |
| **曲线不能跨音符连线** | 用浮点容差分组去猜音符边界，容差取 `1e-9` 会让每个点各自成组。音符边界是**结构**，用"一个音符一段"从数据结构上保证 |
| **采样保持信号必须画阶梯** | 不能把相邻两点连直线 —— 颤音之间的长空白会被画成一条根本不存在的缓坡 |
| **单点轨迹不产生输出** | 轨迹展开需要**相邻两点**；单元音只有一个点 → 输出零音符。修法：永远追加终端偏移 `1.0` |

### 音频 / 频谱类

| 坑 | 症结 |
|---|---|
| **声谱图外层循环必须是 X** | 写成"外层帧"会漏列，图上出现等距**竖**条纹，**极像谐波梳** |
| **谐波在声谱图里是横线**，不是竖线 | 顺带记住 |
| **平滑不能"对数网格 + 线性 Hz 窗"** | δ 状谱线会被系统性拉低约半个窗宽。改成**对数域对称**滑动平均 |
| **噪声源不能用 LCG 取低位** | 周期短 → 变成线谱（一条 172 Hz 的线），会把共振峰位置拉偏十几个百分点。改用 `xorshift32` |
| **取峰不能两边都用 `>=`** | 平坦区会冒出一串 dB 完全相同的假峰。右边必须**严格更大** |
| **按峰值归一 vs 按 RMS 归一** | 按峰值归一会凭空抬高高频。多音混合要按 RMS |
| **PNG 块：长度在前、类型在后，CRC 不含长度** | 自检时发现的 |

### 谱对比的口径（血换来的，不能自创）

- **各自归一化**（0 dB = 本文件自己的峰）⇒ 只比谱形；但文件**内部**的相对差要保留。
- **去均值形状距离**：比之前先减掉各探针的均值，避免"整体倾斜"掩盖形状差异。
- **跨来源对比只用同一套探针**：
  - **1/6 ~ 1/3 倍频程** → 跨来源**谱形**对比（梳状结构不同，粗平滑才可比）
  - **1/24 倍频程** → 频点对账（细峰才分得开）
- **探针窗口决定结论**：用 10% 峰值阈值切段，会把辅音段当成静音**跳过**，
  于是你量到的是元音开头而不是辅音 —— 换个阈值结论就变了。
  → 固定一套探针并写进文档。

## 4. 「能力备好了但产品行为没变」的半成品

半成品比"没做"危险 —— 它会让人误以为"已经支持了"。改代码前先把「已做 / 未做」分清楚。

| # | 状态 |
|---|---|
| `Text_Decoder` | 已实现、已编入核心库，**但没接进 `Lyric_Mapper`**。所以中文歌词目前是空转（解码接口已留好） |
| `--channel N` | 解析了、打印了，**但没人用** —— 通道 1 焊死在 reader 签名里（`NM(path)` / `PM(path, system)`） |
| `--cc11-full-scale N` | 解析了、打印了，**但没人用** —— 响度公式长在绘制层的 private 实现里，转换器链接不到 |
| `FindLeadingConsonant()`（`Formant_Synth.cpp`） | **死代码** —— 改用 `PHON::Resolve()` 之后只剩定义、零调用。读代码时别以为它还在跑 |
| 字典的 `votMs` / `aspirated` | **全死字段** —— 改这两个**不会有任何效果**（送气时长实际由 `noiseMs` 承担） |

## 5. 工具速查

| 工具 | 命令 | 验什么 |
|---|---|---|
| `smf_detect_cli` | `smf_detect_cli <file>` | 输入侧全部读数：PPQN / 拍号 / BPM / 系统 / 弯音 / CC11 / CC7 / 音符 / 歌词 / 绑定 |
| `smf_note_peek` | `smf_note_peek <file> [--track N] [--vel N] [--dump N]` | 逐轨音符配对 / 力度分布 / 时长分布 |
| `make_test_smf` | `make_test_smf` | 生成主测试样本（固定种子，可复现） |
| `make_demo_song` | `make_demo_song <out.mid> [--probe*]` | 生成演示曲；`--probe*` 用来二分排障 |

### ⚠️ `smf_note_peek` 的已知偏差（用它之前必须知道）

它按 **FIFO** 配对同音高的 note_on / note_off。
而"成阻 gate 音符"与"段的第一段"**同 tick、同音高**，
所以 FIFO 会把 gate 的 on 配到段的 off 上
→ **「力度=20 的个数」会被算少**（真实 214 个，工具报 22 个；`dur` 那一列也不可信）。

**看分布形状用它，别拿它的计数当结论。**

### 环境约定

- **`.ps1` 脚本在某些受限环境下加载不了** → 验证工具用 C++ 写，别用脚本抠字节
  （这个项目里，手写脚本抠字节出过的错比被验证的代码还多）。
- 跑 exe 前先设控制台编码为 UTF-8，否则中文提示是乱码（文件本身没问题）。
- **输出重定向 + 只取前 N 行会掐死上游进程** → CSV 只写一半。
  **先落盘再筛。**
- **读 UTF-8 无 BOM 文件用控制台默认编码会乱码、行数也不对**。判断编码 / 行尾**看字节**。

## 6. 改代码前的检查清单

1. **备份。** 这个项目曾经因为一条路径只差大小写的 move 操作，
   毁掉过一个 14.9 KB 的核心源文件，**不可恢复**（无版本控制、回收站为空）。
   → 改任何文件前先复制一份带时间戳的副本。
2. **绝不用只差大小写的路径做 move / delete**（Windows 文件名不分大小写）。
3. **改了合成参数 → 所有验收样本必须一起重新生成。**
   曾经改完只重生成了一份、忘了另外三份，
   结果拿旧的输出当新的听，以为代码没改对。
4. **改字典之后重跑探针**，看有效签名 / 塌陷组有没有变化。
5. **改输出侧参数前先确认它有没有被接线**（见 §4）。

三分钟就能确认的事，别花三十分钟推理。
